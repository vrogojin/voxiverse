# AGENTS.md — entry point for coding agents

VOXIVERSE is a Minecraft-like voxel simulation engine written in Godot 4.4.1 with the Zylann
`godot_voxel` C++ module, exported to a threaded WebAssembly build and served at
https://voxiverse.game-host.org. The world is a 1:1000-scale faceted planet (radius 6371 blocks,
`godot/src/cosmos/facet_atlas.gd`) that you can walk on, fly over, orbit and de-orbit to, with a
multi-tier far-render LOD ladder. Agent know-how from July to September 2026 is in `docs/knowhow/`.

Read in this order: this file, `CLAUDE.md` (build pipeline, core engine rules), `docs/DESIGN.md`
(original locked scope), `docs/knowhow/README.md` (how the notes are organised),
`docs/knowhow/OPEN-WORK.md` (unfinished threads). Where a note contradicts the code, the code wins.

## Architecture in one screen

- **Engine.** Custom Godot 4.4.1 editor and Web templates built in Docker with godot_voxel v1.4.1
  plus local patches in `docker/engine/patches/{godot,godot_voxel}/` (web pthread pool size, malloc
  choice, allocation probes, the C++ world generator `0007-cosmos-cpp-generator.patch`, parallel tile
  bake, structure generation, ...). Pins live in `docker/engine/versions.env` (emsdk 3.1.64,
  `WEB_MALLOC=dlmalloc`, `WEB_PTHREAD_POOL=24`). Renderer is `gl_compatibility` (WebGL2), threaded
  export (`godot/export_presets.cfg`, `variant/thread_support=true`). Details: `docs/ENGINE-BUILD.md`.
- **Game code** (`godot/src/`). `main.gd` assembles the scene in code; `world/world_manager.gd` owns
  the world; `WorldManager.block_id_at()` is the single cell query (edit overlay over generated
  terrain); player physics is analytic, not a trimesh (see `CLAUDE.md`). `cosmos/cube_sphere.gd` is
  both planet math and the registry of about 298 `FP_*` feature flags. `sim/` holds the decoupled
  material/environment/weather layer. `tools/` holds the headless gates (`verify_*.gd`), probes and
  benches.
- **Faceted planet.** Piecewise-flat facets (`FACET_K` = 24, i.e. 24x24 per cube face, 3456 facets for Earth,
  `cosmos/body_lod.gd`), undistorted cubes per facet, curvature only at seams
  (`docs/knowhow/agent-notes/voxiverse-faceted-planet.md`, `docs/COSMOS-FACETED-IMPL.md`). Seam,
  datum and frame bugs were the largest bug class (see the "Faceted planet" group in the README).
- **Near field.** godot_voxel `VoxelTerrain` around the player on the active facet plus full-res edge
  neighbours (`world/voxel_module/module_world.gd`, `FP_NB_FULLRES`), generated by the C++
  `VoxelGeneratorCosmos` (`FP_CPPGEN`, byte-equal to the GDScript `world/terrain_config.gd`;
  `voxiverse-l5a-cppgen.md`). A pure-GDScript fallback mesher (`world/fallback/`) still exists.
- **Far LOD ladder** (outward from the player): near voxels; smooth near-fill
  (`world/facet_smooth_v2.gd`); the whole-planet far shell `world/facet_far_ring.gd` (blocky emission
  `FP_BLOCKY_FARRING`) textured by the fine map / band skin baked in `world/facet_tex_baker.gd`
  (C++ tile bake); `world/facet_orbit_relief.gd` (DEM-displaced relief from orbit,
  `world/global_relief_data.gd`). Overlays: far trees `world/facet_far_trees.gd` (mini-mesh, then
  cross cards to about 2400 blocks, then fine-map canopy; `voxiverse-far-trees-design.md`), far
  villages `world/facet_far_structures.gd` (merged cube mesh near, impostor cards beyond
  `STRUCT_CARD_MIN`, `world/struct_card_kit.gd`), physical objects `cosmos/object_lod.gd`.
- **Streaming.** `world/stream_load_controller.gd` (credit governor), `world/job_lane.gd`, Godot
  `WorkerThreadPool`, godot_voxel threads in `godot/project.godot` `[voxel]`; the web main thread is the bottleneck.
- **Space.** Orbit and navigation use an f64 body-centred inertial state (`cosmos/orbital_state.gd`,
  `cosmos/cosmos_nav.gd`, `cosmos/cosmos_gravity.gd`, `cosmos/cosmos_ephemeris.gd`;
  `voxiverse-spacenav-design.md`, `voxiverse-two-gravity-systems.md`). Moon/multi-body and weather
  exist behind default-off flags (`MULTI_BODY`, `SOI_SWAP`, `FP_CLOUDS`, `FP_PRECIP`).
- **Serving.** `docker/server/` builds an nginx image that sends COOP/COEP on every response
  (required for `SharedArrayBuffer`; without it the page is blank) and serves precompressed `.gz`
  siblings. `scripts/deploy.sh` regenerates the `.gz` files, starts the container on the external
  `haproxy-net` network, registers with HAProxy and verifies headers (`docs/DEPLOY.md`).
- **Remote bridge (agent observation and control).** The game (`net/remote_bridge.gd`,
  `net/remote_bridge_activator.gd`) dials out to `wss://<site>/remote` when opened with
  `?remote=<token>` or Ctrl+Shift+F9; nginx proxies to a relay container (`tools/remote-bridge/relay.mjs`)
  that writes `results/telemetry.jsonl` and frames for the agent. Control (scripted flights via
  `tools/remote-bridge/flight.mjs`, agent skills in `net/agent_skills.gd`, `net/agent_nav.gd`) needs
  a second secret and in-game human consent, and `CONTROL_ENABLED` is false in source
  (`tools/remote-bridge/README.md`, `docs/AUDIT-REMOTE-BRIDGE.md`, `voxiverse-mission-control.md`).
  Tokens are host-local gitignored files; never commit them.

## Feature flags: the most important thing to understand

- Every change since mid-July ships as `const FP_X := false` (almost all in
  `godot/src/cosmos/cube_sphere.gd`). With all flags at their defaults, `main` is byte-identical to
  before the change; this is proven by the FLAT gate (`verify_feature.gd`) count staying the same.
- **Source defaults are not what is live.** Even `FACETED := false` (line 47): `main` exported as-is
  is the old flat world. The live build turns on about 212-217 flags at export time by `sed`, then
  reverts the source (`voxiverse-deploy-cheats-pipeline.md`).
- **The served flag list is not in the repo.** The script that held it (`deploy_cheats.sh`) lived in
  an agent scratchpad and was never committed. Recover the set from the live build: download
  `index.pck`, load it headlessly (`ProjectSettings.load_resource_pack` or `--main-pack`) and call
  `get_script_constant_map()` on `res://src/cosmos/cube_sphere.gd` (`voxiverse-atmo-sky-design.md`,
  `voxiverse-fartree-shift-residual.md`). Do this before any live deploy.
- Flags that must stay off in the live set (per the old script): `FP_RADIAL_DATUM`, `FP_CLOUDS`,
  `FP_PRECIP`, `FP_STORMS`, `FP_TIER_DEPTH_BIAS` (`voxiverse-deploy-cheats-pipeline.md`).

## Build, test, export, deploy

```bash
scripts/build.sh          # Docker: engine + web templates (~24 min cold). SKIP_WEB=1 / SKIP_LINUX=1 / --rebuild
scripts/export-web.sh     # Docker: headless export of preset "Web" -> build/web/
scripts/deploy.sh         # nginx container + HAProxy registration + live verify. --no-build / --staging / --test-mode
scripts/render-soak.sh    # Xvfb + llvmpipe rendered soak with golden compare (godot/test/soak_goldens)

# FLAT gate (byte-identity), and any feature gate:
docker/engine/bin/godot.linuxbsd.editor.x86_64 --headless --path godot --import        # once per fresh worktree
docker/engine/bin/godot.linuxbsd.editor.x86_64 --headless --path godot --script res://src/tools/verify_feature.gd
```

- Without `--import`, a fresh worktree shows 15 texture failures that are not regressions
  (`voxiverse-flat-gate-import.md`). The FLAT count drifts (6042/0 at PR #84); compare base vs change.
- Feature gates (`verify_<feature>.gd`) are run with the relevant flags temporarily `sed`-ed to
  `true` in `cube_sphere.gd`, then restored with `git checkout`. Run gates one at a time per worktree;
  concurrent flag flips corrupt `cube_sphere.gd` (`voxiverse-deploy-cheats-cs-rb-revert-trap.md`).
- A Godot export does not fail on GDScript parse errors. After every export, grep the log for
  `Parse Error|SCRIPT ERROR|Cannot find member` (same note).
- Engine-patch changes: edit copies outside the git-ignored `docker/engine/cache/` (it was observed
  to revert edits), produce patch files, check with `git apply --check`, and add any new godot_voxel
  `.cpp` to the module's explicit source list; new `versions.env` knobs must also be forwarded by the
  outer `scripts/build.sh` (`voxiverse-gen-convoy-stage1-patches.md`, `voxiverse-mimalloc-fit-build.md`).
- No GPU on the original build host: headless gates prove logic only; rendered checks use
  `scripts/render-soak.sh` (timings meaningless) or a cloud GPU (`tools/web-soak-gpu/`); real
  performance was measured in the user's browser via the remote bridge
  (`voxiverse-gpu-headless-testing.md`, `voxiverse-web-testing-host.md`).
- `scripts/deploy.sh` and `deploy/docker-compose.yml` hard-code paths of the original host; adjust them.

**Live A/B procedure (as practised; recreate it as a committed script).** (1) Commit any new flag or
constant in `cube_sphere.gd` / `remote_bridge.gd` first; the pipeline reverts these two files and
uncommitted edits there are wiped, leaving dangling references and a broken build
(`voxiverse-deploy-cheats-cs-rb-revert-trap.md`). (2) `sed` the chosen flag set to `true` (plus
`CONTROL_ENABLED` for dev cheats), verify every flag reads `true` and the must-stay-off set is false.
(3) `scripts/export-web.sh`; grep the log for parse errors. (4) `scripts/deploy.sh --no-build`.
(5) `git checkout --` both files. (6) `curl` the site: HTTP 200, both COOP/COEP headers,
`index.wasm`/`index.pck` last-modified. (7) Dump the served pck's flags to confirm what is live.
GDScript-only changes need no engine rebuild (minutes, not 24 minutes).

## Repository and branch conventions (as actually used)

- Feature branches off `main`: `feat/voxiverse-*`, `fix/voxiverse-*`, `perf/*`, `docs/voxiverse-*`;
  merged by GitHub PR into `main` (for example PRs #74-#77, #83, #84). `CLAUDE.md` and
  `docs/DESIGN.md` §7 still name `feat/voxiverse-bootstrap`; that rule is out of date.
- Conventional Commits with scope `voxiverse`; types in use include `feat`, `fix`, `perf`, `docs`,
  `test`, `instr` (measurement-only), `wip`, `chore`, `merge`.
- `deploy/*` branches (`deploy/perf-plus-sky`, `deploy/cheats-eyeball`) were integration branches
  for live builds, built from a separate "deploy" worktree with symlinked toolchain. Gotcha: when
  dumping served flags, use the pck in that deploy worktree's `build/web/` (or the live site), not
  the main checkout's stale one (`voxiverse-fartree-frame.md`, lesson 1). `backup/*` and `wip/*`
  remote branches are snapshots of local worktrees, not maintained work.
- Every non-trivial change gets a design doc `docs/COSMOS-<TOPIC>-DESIGN.md` first, then a headless
  gate, then an independent adversarial review (another model), then a live A/B. PR #84's
  description (`docs/knowhow/agent-reviews/pr84-body.md`) is a good template.
- `docs/ROADMAP.md` mirrors a GitHub Project board (`roadmap-board-sync.md`).
- Hard constraints from the owner: the live web demo must load and stay playable
  (`docs/DESIGN.md` §7); never risk out-of-memory on web, memory-costly upgrades ship flag-gated
  behind a measured A/B (`voxiverse-never-oom-web.md`); walk, fly and orbit must be one seamless
  continuum (`voxiverse-seamless-scales.md`); planetary parameters must be per-body, not
  Earth-hardcoded (`voxiverse-generic-body-params.md`); physics dormant by default
  (`voxiverse-physics-scale.md`).

## Verification discipline (lessons that recurred)

1. **A/B the premise before building the fix.** A 72% vertex cut moved fps by zero because the
   frame was vsync-bound (`voxiverse-backstop-diet.md`); a whole allocator arc chased spikes while
   the felt problem was elsewhere (`voxiverse-gen-convoy-mechanism.md`).
2. **Check the measurement rig first.** The relay telemetry itself causes 200-450 ms hitches; most
   reported ground "jerkiness" in late August was observer effect. Judge feel on the bare URL with
   no `?remote=`; use counters, not frame times, over the relay (`voxiverse-gen-convoy-mechanism.md`,
   `voxiverse-forest-fps-limiter.md`, `voxiverse-near-radius-diet.md`).
3. **Reason from the served flag set, never from source defaults** (`voxiverse-stream-idle-diet.md`,
   `voxiverse-border-shade-weld.md`, `voxiverse-atmo-sky-design.md`).
4. **Assert cost and duration, not only rate or structure.** A gate passed on commit rate while a
   250 ms per-commit stall slipped through (`voxiverse-orbit-relief-g3.md`, process lesson 3).
5. **Count draw calls before theorising about fill or early-Z** (`voxiverse-near-leaf-cutout.md`).
6. **A parameter fitted to one observation is zero evidence**; measure signs and coefficients from
   the data structure (`voxiverse-seam-mask-fallthru-law.md`, `voxiverse-far-near-coverage.md`).
7. **Do not condition perf stats on the streaming state** (`voxiverse-streaming-supply-demand.md`).
8. **Web timing signals:** `Performance.TIME_PROCESS` is meaningless on the threaded web build; use
   real frame deltas and p90, not window max (`voxiverse-web-time-process-invalid.md`).
   `OS.get_processor_count()` under-reports on web; use the `cores` telemetry
   (`navigator.hardwareConcurrency`) (`voxiverse-web-core-count.md`).
9. **Instrument the un-gated work.** A delta gate is only as cheap as computing its inputs; the
   village jerk was an uncounted O(N) prelude, which five counted-work fixes missed
   (`voxiverse-village-bake-memo.md`).
10. **Uncontrolled live A/Bs are noisy** (respawn location, house count, warm-up); prefer a
    controlled headless bench on the same inputs (`voxiverse-village-bake-memo.md`,
    `godot/src/tools/bench_struct_bake.gd`).
11. **Unit gates that call a subsystem directly cannot catch dead wiring** in the main loop or a
    forward to the wrong object (`voxiverse-orbital-shell.md`, `voxiverse-deorbit-phys-fix.md`).
12. **Headless green is not sign-off for render paths.** New RenderingServer/GL paths need a live
    boot probe; visual fixes need the user's eyes, not your own screenshots
    (`voxiverse-far-smooth-geometry.md`); re-enable one flag at a time (`voxiverse-lod-texture.md`).
13. **Gate synthetics must model what the engine actually loads** (`voxiverse-mesa-viewband.md`),
    and coverage probes must be clamped to meshed bounds or they latch dead
    (`voxiverse-grassbase-backstop.md`).
14. **Telemetry fields can be sticky maxima or stale latches** (`wf_st_bms`, the smooth_v2 commit
    time); window samples alias sub-window excursions (`voxiverse-ground-walk-perf.md`,
    `voxiverse-stream-idle-diet.md`).
15. **Verify agent and design-doc citations**: file:line references were hallucinated at least once
    (`voxiverse-web-core-count.md`). GDScript lambdas capture by value, so closure-based gate drivers
    silently never advance (`voxiverse-gdscript-closure-trap.md`).

## Hard-won technical gotchas

- Every per-facet bake or build must run off the main thread or be budget-sliced with the check
  before each unit, or orbit and walking hitch (`voxiverse-lod-texture.md`).
- GLES3 MultiMesh: a custom-data-only MultiMesh read by a COLOR-reading shader aliases slots; use
  colors plus custom (`voxiverse-far-trees-colorfix.md`). `set_instance_transform` is a no-op on a
  MultiMesh filled via `set_buffer` (`voxiverse-fartree-polish132.md`).
- Under `world_vertex_coords`, `VERTEX` arrives in world space (planet-radius magnitudes); impostor
  shaders must reconstruct local position from UVs (`voxiverse-village-bake-memo.md`, Stage 2).
- Far tiers anchored via `lattice_to_world64` must add `datum_lift`, or they sit below the sphere
  (`voxiverse-fartree-frame.md`); near-field shaders must not assume planet centre = origin
  (`voxiverse-night-terrain-centre.md`).
- "Near field covers it" is false off-surface; regime-gate coverage assumptions
  (`voxiverse-orbital-shell.md`).
- Remote flight legs reject wrong keys (`set_time` takes `local_hours`; `freeze_*` need `on`); a dark
  frame is usually night, not a render bug (`voxiverse-remote-bridge.md`). Restarting the relay
  drops the control grant (`voxiverse-block-lod-design.md`).
- Never rest physics bodies on a many-quad trimesh; use a heightmap or boxes (`voxiverse-project.md`).
- A biome-enum collision between Earth and Moon ids caused missing tree collision; use the
  per-body helpers (`voxiverse-tree-bugs-rootcause.md`).
- Stale note claims found at import: `voxiverse-project.md` says voxel threads are pinned to 1, but
  `godot/project.godot` now sets minimum 3; `voxiverse-backstop-diet.md` says `FP_SHELL_SURF_CAP` is
  not merged, but it is on `main` and commit `6d58454` treats it as served; `voxiverse-village-bake-memo.md`
  calls `FP_STRUCT_LOD` unimplemented, but `verify_structures.gd` has a roof-skin gate for it (`f4600d9`).

## Recreating the live game world

The served build runs with 234 GDScript feature flags ON that the committed source keeps at `false`:
233 in `godot/src/cosmos/cube_sphere.gd`, plus `CONTROL_ENABLED` in `godot/src/net/remote_bridge.gd`.
They were recovered from the last archived live pack.

- `docs/knowhow/live-flags/live-flags.json` is the flag record. It is the source of truth; do not inline
  copies of it elsewhere.
- `docs/knowhow/live-flags/LIVE-FLAGS.md` explains how the list was derived and groups the flags by theme.
  It also lists the must-stay-OFF set and the limitations.
- `docs/knowhow/live-flags/extract_pck_flags.py` is the parser for the PCK and GDScript binary tokens.
- `scripts/deploy_cheats.sh --dry-run` checks the flips. Without `--dry-run` it flips, verifies,
  exports and restores the files. `--deploy` also serves the build.
- Commit any edits to those two files before a real run; the restore step wipes uncommitted changes.
