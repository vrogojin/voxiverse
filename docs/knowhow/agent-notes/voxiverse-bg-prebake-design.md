**ROOT CAUSE of the "ugly facet-in-front" (live facet 1716 alt 195 looking down, fm_baked=0 bm_res=0/want=49 cpp_on=False) = cause (a): fine-map AND band tiers UNBAKED at a fresh on-surface region → shader falls to the COARSE BASE page (16 texels/facet ≈26 blk/texel, filter_linear_mipmap).** The blur + tone-mismatch + diagonal line are ONE artifact = a RESOLUTION discontinuity vs neighbour facets that already baked band/fine (1-6.5 blk/texel). NOT a tier-blend seam, NOT smooth/far-ring/skin boundary, NOT a colour-law bug (FP_FAR_COLOR_UNIFIED is ON, hue already unified). Shader fallback fine→band→base at facet_far_ring.gd:4482-4506.

**Why fm_baked=0/cpp_on=False (both EXPECTED on-surface, NOT bugs):** (1) FP_FINE_BAKE_SURFACE_PAUSE ON → whole-planet fine tier dispatches NO new bakes on-surface (facet_tex_baker.gd:1844 `if not fine_pause_on or _offsurface`), so it only holds facets baked while OFF-surface → a never-orbited teleport = fm_baked=0. (2) On-surface web the band runs at 1 WORKER (facet_tex_baker.gd:1776 `active = _pbm_n if (_pbm_tile_ok and _offsurface) else (1 if web else _pbm_n)`), ~1 facet/s → bm_res=0/want=49 = the 49-facet SSE disc mid-fill. (3) `cpp_on` telemetry (facet_tex_baker.gd:2054) tracks FP_CPP_FINE_BAKE — a SHELVED flag NOT in the deploy set — AND is _offsurface-gated → always False on-surface = RED HERRING. The SHIPPED C++ fast path is FP_CPP_TILE_BAKE (patch 0011), which is ALSO _offsurface-gated in dispatch (_pbm_tile at :1828/:1860) → dark on-surface. THAT gate is the real lever.

**MEMORY — the critical number: the whole-planet fine tier ALREADY EXISTS + is ALREADY bounded at ~27 MB FIXED** (FP_PLANET_MAP: 24 L8 sub-pages of 768² = 12(PLANET_MAP_QUAD)×64(PLANET_MAP_TEXELS, 6.5 blk/texel), 13.5MB CPU + 13.5MB GPU; facet_tex_baker.gd:2106-2110, cube_sphere.gd:658). ~1.3% of the 2048MB WASM ceiling; measured live heap 412-495MB. It's a flat-COLOUR skin, NOT the infeasible ~158MB full-res L5 GEOMETRY globe ([[voxiverse-block-lod-design]]). ⇒ **the background prebake needs ZERO new resident memory — it fills a tier already on the NEVER-OOM ledger. FITS with 1.5GB to spare; NO bounded compromise needed. The constraint was never memory — it's fill-PACING on 2 cores.**

**DESIGN = FP_BG_PREBAKE (scheduler change, not data-structure):** lift the on-surface fine pause under a FRAME-TIME GOVERNOR (dispatch only when last proc_ms < ~22ms, ≤1 background slot on-surface = the measured non-convoy optimum), fill VIEW-CONE-FIRST (active∪ring first → the facet-in-front sharpens in ~1-2s, then the disc, then cursor-sweep the rest of the planet), routed through the C++ tile bake on-surface (sub-flag FP_BG_PREBAKE_CPP; the TILE baker holds its OWN reader-parallel RWLockRead generator instance so it SHOULD be surface-safe — unlike the shelved FINE baker FP_CPP_FINE_BAKE that froze at 1.5fps on the SHARED lock; this is the one live-A/B unknown, isolated behind the sub-flag w/ GDScript fallback via the existing _pbm_tile_ok refusal latch). Whole planet fills over a couple min of idle headroom, imperceptibly; once swept a fresh teleport never shows base again. Flags off = byte-identical to shipped FP_FINE_BAKE_SURFACE_PAUSE. Gate verify_bg_prebake: G-BGP-OFF byte-off+FLAT 6042/0, G-BGP-COVERAGE (view-first order + whole-planet completeness), G-BGP-BUDGET (ZERO added bytes), G-BGP-PACING (no dispatch on injected hot frame), G-BGP-CPP-DEGRADE; live A/B = teleport to never-orbited facet, blur clears ≤2s + fps≥45 + heap flat.
