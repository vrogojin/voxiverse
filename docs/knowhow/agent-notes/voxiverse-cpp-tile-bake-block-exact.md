2026-08-02 SHIPPED LIVE (commit 065d5ba on deploy/cheats-eyeball, wasm 21:14:38): the C++ lock-free parallel far-skin sampler + biome-exact texture-honest far colours. Full team cycle (Fable design ×2 + cpp-pro C++ ×3 + gates).

**Root cause of the bake never parallelising on web (Fable, REFUTED the lock theory):** the general Godot WorkerThreadPool defaults to ONE thread on the web export (`OS_Web::get_default_thread_pool_size()==1`); project.godot never set `threading/worker_pool/max_threads`. The `[voxel]` `threads/count/*` keys are godot_voxel's SEPARATE pool; WEB_PTHREAD_POOL is the emscripten pthread pool — both different. So the `_pbm_n` bake slots were time-sliced on 1 thread, never concurrent. NOT the C++ `_params_lock` (that's a per-instance reader-parallel RWLockRead; the baker holds its OWN generator instance). Also dlmalloc (this branch, NOT mimalloc) busy-waits the browser main thread.

**FP_CPP_TILE_BAKE (patch 0011):** new const `VoxelGeneratorCosmos::bake_far_tile(fid, lat_corners, nx, ny, tex, edit_cells, edit_far_idx)` runs the WHOLE tile texel loop in native C++ (one RWLockRead/facet, edit→tree→terrain, integer-LUT byte-equal via canon_idx + deco_far_idx). F2 capacity: WEB_PTHREAD_POOL 16→24 + project.godot `worker_pool/max_threads.web=5` + `low_priority_thread_ratio.web=0.8` (→4 concurrent bake threads). F3: `_pbm_n=clamp(min(cores-2,4),1,4)`, OFF-SURFACE-gated (surface caps to 1 slot on web = the measured GDScript optimum; near-field cores stay free). `_detect_cores()` reads navigator.hardwareConcurrency (Godot web OS.get_processor_count UNDER-reports: 2 on an 8-core host).

**FP_SKIN_BLOCK_EXACT (user directive "colors MUST correspond exactly to block textures; biomes define block textures"):** both bake paths classify a surface column as `far_color_index_of_block(TerrainConfig.top_block_id(...))` — the ACTUAL surface block's texture mean — NOT color_for's synthetic biome-blend. top_block_id law: g<SEA_LEVEL→ice/lava/water (_sea_block, t<-0.55 / LAVA_SEA_T=0.60); else biome_top (or bedrock@B_PILLAR), snow_block iff CAPPABILITY-GATED (state_mask STATE_SNOW_CAPPED) AND surface_temperature<0 (mirror _with_snow_state — NOT the design's simpler unconditional snow). Savanna/jungle GROUND = grass mean (worldgen surfaces grass there); biomes differentiate via acacia/jungle/cactus TREES. **Fable Q2 finding: the C++ generator had NO Whittaker classifier + NO acacia/jungle/cactus species — under FP_CLIMATE_BIOMES it computed different biomes AND drew no B1 trees; cpp-pro ported them byte-exact (hash salts 121/122/123/124/125), which ALSO closed a latent FP_CPPGEN+FP_CLIMATE_BIOMES near-terrain divergence (near+far now share Whittaker).** 7 config keys emitted from the shared TerrainConfig.material_tables() so near-field + far gens agree.
