2026-08-09 DESIGN/root-cause (analysis-only): docs/COSMOS-FAR-TERMINATOR-DESIGN.md on deploy/cheats-eyeball (task #98). User bug: at local night NEAR terrain darkens correctly but a FAR-render border/strip shows bright DAY-lit green (facet 435). Team-lead suspected the terminator was missing / used the wrong origin-relative normal (like the near FP_NIGHT_TERRAIN_CENTRE bug) / or was solved-then-rolled-back.

**FINDING: NONE of those. The far terminator is PRESENT, CORRECT (centre-relative radial, NOT origin-relative), LIVE-FED, and UNIFIED near==far by construction across EVERY far tier.** Code-verified: shared law VoxiLight.voxi_shade(n,sun_dir) (voxi_light.gd:42-56, shade=max(night_floor 0.06+(1-nf)*_day(mu), moonshine 0)) is string-included into: shell/fine-skin/blocky-far-ring sm2 (facet_far_ring.gd _SHELL_ABS_TEX_LIGHT:4218-4226 + _apply_shade_unified:4562), near module atlas twin (block_atlas.gd:93/118), BlockMaterials near per-id twins, Smooth-V2 annulus (facet_smooth_v2.gd:258-262), TierPlace biased tier (tier_place.gd:258-264 unified variant). ALL use n=normalize(wp-centre), centre=MODEL·0; the shell transform is Transform3D(Basis.IDENTITY,-_anchor_offset) (facet_far_ring.gd:1027) so wp-centre=VERTEX=exact body-fixed radial. current_sun_dir() (cosmos_sky.gd:101) is Earth BODY-FIXED frame = the scene frame (planet pinned identity) = the frame near+far vertices live in. main.gd:307-322 pushes current_sun_dir() to shell(308)/near(313)/smooth_v2(322) every frame under the live flags (FP_SHELL_ABSOLUTE+FP_SHADE_UNIFIED+FP_NIGHT_TERRAIN_CENTRE+FP_SMOOTH_V2 all ON). So near-dark ⇒ far-dark BY CONSTRUCTION. FP_SMOOTH_V2_LIT (rolled back) is RELIEF slope-shading, a DIFFERENT axis from the terminator — correctly stays off.

**Physical (across-terminator) RULED OUT: at alt 195 the horizon is only ~√(2Rh)≈1576 blk≈14° arc (R=6371); at local midnight the visible far is <14° from observer = still deep night. Bright-green far at midnight = bug not physics.**

**⇒ The live bug is a RUNTIME sun_dir delivery gap (static code cannot reproduce — all pushes fire).** PRIME SUSPECT (candidate 1): the Smooth-V2 annulus — a SEPARATE material from the shell, rebuilt on facet crossings; _make_material (facet_smooth_v2.gd:296-301) seeds sun_dir=(1,0,0)=+X DAY; if the instance/material is recreated on a re-anchor and set_sun_dir doesn't land that frame, the hop-2..4 annulus renders against a FIXED +X day-sun = a bright day-lit MID-RING strip while shell+near track live time. This is EXACTLY the FP_BLOCK_LOD "frozen at default sun (1,0,0)" failure main.gd:300-306 documents+backstops for the block-LOD tiers with an UNCONDITIONAL write — the smooth-V2 push has NO such rebuild-safe backstop.

**DISAMBIGUATION (one live capture): add per-tier sun_dir echo telemetry (get_shader_parameter("sun_dir") → sd_shell/sd_v2/sd_near). If sd_v2≈(1,0,0) while others=live night sun → candidate 1 confirmed. Else A/B toggle FP_SMOOTH_V2 off then FP_PLANET_MAP off, see which strip vanishes.** FIX = FP_FAR_TERMINATOR_WELD: single-authority unconditional + REBUILD-SAFE sun_dir re-assert to all far materials (seed new materials from a cached _last_sun_dir not the (1,0,0) default); terminator only, relief untouched (FP_SMOOTH_V2_LIT stays off).
