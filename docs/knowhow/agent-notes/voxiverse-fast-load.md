Slow fresh-reload (2-3min at 4-28fps) fix. Root cause (profiled LIVE, docs/COSMOS-FAST-LOAD-DESIGN.md, Fable fable-load-arch): NOT the near field (vox_main~0, vt_total~0.1) and NOT a worker/dlmalloc convoy (browser has 8 cores, pbm_busy 1/4 = workers IDLE) — a MAIN-THREAD PILE-UP of DEFERRABLE far/background work while the near view isn't up. Ranked: smooth_v2_commit_ms=185 DOMINANT (FacetSmoothV2._commit whole-annulus: merge_tiles per-index GDScript idx-shift over ~630k indices + commits on EVERY reap ~36x = O(N²) + runs from boot above FP_BOOT_ASYNC), env_converge_ms=29, snow_ms=20-25. CORRECTIONS: setpoint_ms=38 is NOT a cost (StreamLoadController adaptive threshold); phys/tex leave. KEY: stream_credit=0 = priority INVERSION (controller throttles ONLY the near field while the far/sim work that caused the overload BYPASSES it) → deferral has a 2nd-order credit-recovery win (worst-EMA drops below setpoint → near ramp un-throttles onto idle workers).

PHASE 1 FP_LOAD_DEFER (MERGED PR #42, main ed3fcdc): one WorldManager._load_settled latch flipped once off initial_view_meshed 64³ probe (the FP_DEM_DEFER shape) + LOAD_DEFER_FAILSAFE_MS=45000 wall-clock backstop, boot-once. Pre-settle: smooth_v2.step REAP-ONLY (no dispatch/commit, the FP_ORBIT_RELIEF WS1a pattern), env far-ring held in FP_ENV_FALL_HOLD cover-only branch, SnowfallSystem step skipped (not FP_LOAD_DEFER or _load_settled). Paced resume dispatch-first/commit-later, first commit waits stream_credit>0. Byte-off: latch stays false forever. LIVE: smooth_v2_commit_ms=0 through entire load (was 185/frame), worst_ms ~halved 626→335. Gates verify_fast_load G-FL-OFF/GATE/FAILSAFE 27/0 + FLAT 6042/0.

PHASE 2 FP_SMOOTH_V2_PACE + FP_SMOOTH_V2_ASYNC_MERGE (MERGED PR #43, main 56f7474): makes each POST-settle smooth_v2 commit cheap (it hitched play on crossings/view-changes). PACE = rate-cap commits SMOOTH_V2_COMMIT_MS=500 (G3 should_commit pattern), ~36→5-8 commits. ASYNC_MERGE = merge_tiles off-thread on a shallow immutable-tile snapshot (single-slot never stacked), main pays only add_surface_from_arrays + mesh swap (SAFE API, no RenderingServer region calls), canonical ascending-fid order preserved ⇒ BYTE-IDENTICAL to sync. Async byte-eq PASSED (didn't fall back). MEASURED native: sync commit 30.6ms → async main residue 4.4ms (merge ~26ms off-thread, ~85% off main; web 185ms→~14.5ms live confirmed with 35 tiles). Gates verify_fast_load 41/0 (+G-FL-PACE + G-FL-MERGE-EQ byte-equality across many tile sets + CoW stress), FLAT 6042/0, verify_far_smooth 515/0 (G-V2-PURE intact). Kill switch: drop _ASYNC_MERGE alone keeps the safe pace win.

RESIDUAL (smaller, separate): after both phases, load worst_ms still ~264-360 mid-load from the near-field streaming (untracked module apply) + steady snow/env post-settle. The reload is meaningfully better (worst halved + smooth_v2 hitch gone) but not instant. LESSONS: (1) profile the load with the *_ms telemetry breakdown before assuming "convoy" — the named "near-field convoy" was actually FAR-tier + sim work; (2) an idle-worker + high-proc + zero-tracked-subcost signature = untracked/deferrable main work OR off-thread-movable compute; (3) async off-thread merge is safe ONLY with a byte-equality gate (G-FL-MERGE-EQ) proving the thread hop is byte-identical — surfaces any WASM CoW race; (4) is_task_completed reap is unreliable in a frame-less headless SceneTree (gate must wait_for_task_completion; production reap is correct on frame-pumped web). (5) remote reload-thrashing makes precise time-to-usable hard to measure — rely on the mechanism (smooth_v2=0 during load) + native timing + worst-frame delta.
