BUILD-#1 RESULT + BUILD-#2 (lock probe): the alloc probe FALSIFIED alloc-stall as dominant — main-thread alloc is only ~14% of the walk spike; profs+prewarm cut alloc PEAKS (max main-alloc 1780→378 ms/s) but not the felt floor (worst_ms p90 290→292). So NO recycler. Re-attribution: spikes are worker-flooded GENERATION (wf_vox_gen 51×, wf_pool_active up to 6), NOT render/apply/alloc → main-thread busy-spins (no Atomics.wait on WASM) on a NON-malloc engine lock. Build #2 = a main-thread lock-WAIT probe: `docker/engine/patches/godot_voxel/0017-cosmos-gen-convoy-lock-probe.patch` (new `util/thread/lock_probe.{h,cpp}` + instrument `rw_lock.h` read/write_lock → ZN_LOCK_RWLOCK and `mutex.h` MutexImpl::lock → ZN_LOCK_MUTEX; reuses ZN_VOX_ALLOC_PROBE compile gate, runtime flag `FP_GEN_LOCK_PROBE`; surfaces `wf_lock_rwlock_ms`/`wf_lock_mutex_ms`). LOCK CENSUS: the hot main-acquired RWLock is `VoxelData::Lod::map_lock` (storage/voxel_data.h:364) — during a gen flood it's main-apply-WRITE (insert each generated block) vs main-stream/query-READ serialization (the mesher's map read is commented out, mesh_block_task.cpp:468), i.e. main-vs-main, unmetered. The worker-contended Mutex is ThreadedTaskRunner `_completed_tasks_mutex` (threaded_task_runner.h:161) — main drains (voxel_engine.cpp:144) vs 6 workers push (:367). My lean: rwlock (map) is the larger. The probe A/B decides the real floor.

KEY ALLOCATOR FINDING (decides recycler Candidate A vs B): **`memnew` bypasses class `operator new`** — `memnew(T)` = global placement `::new("") T` → `Memory::alloc_static` (core/os/memory.h:130), and `memdelete` calls `Memory::free_static` directly (:140). So overriding a class's operator new/delete does NOT catch memnew'd objects. Candidate A (module VoxelBuffer recycle) must therefore use a `shared_ptr` custom deleter over a free-list (the recycle hook fires wherever the last ref drops — no data-map lifecycle surgery). Candidate B (core `alloc_static` slab front-end) is the only thing that transparently catches memnew objects + CoW `Packed*Array` backings, but it's the higher corruption-risk piece. All CoW backing routes through `Memory::alloc_static` (cowdata.h:313/368/424, `pad_align=false` → raw malloc in release, no size header).

DEPLOY GOTCHA (bit us 2026-08-30) — the deploy pipeline (`deploy_novillage.sh` / deploy_cheats) runs `git checkout -- godot/src/cosmos/cube_sphere.gd godot/src/net/remote_bridge.gd` at start/abort to strip the flag-flip sed after export. This **WIPES uncommitted glue** in those two files — if `module_world.gd` (not reverted) still forwards `CubeSphere.FP_GEN_*` consts, they become dangling refs → crash on load. FIX: **commit the GDScript glue before deploying** so the checkout reverts to the committed (correct) version and the sed flips flags on top. Same trap noted in [[voxiverse-fallthrough-loc-bug]].

BUILD-SYSTEM GOTCHA (0017 link-failed on it) — a NEW godot_voxel module `.cpp` is NOT auto-compiled: `common.py:get_sources()` holds an explicit list of glob patterns, and it is NOT recursive. Some dirs are globbed (`generators/cosmos/*.cpp`, `storage/*.cpp`, `util/*.cpp`) but **`util/thread/` is listed FILE-BY-FILE** (`thread.cpp`, `spatial_lock_2d.cpp`, `spatial_lock_3d.cpp`) — so a new `util/thread/lock_probe.cpp` must be added to that list explicitly or it never links (wasm-ld: undefined symbol from the header wrappers that call it). `git apply --check` passes regardless — only the build catches it. Patch 0007 established the mechanism (append the source to `common.py`). Any patch adding a new module TU MUST include a `common.py` registration hunk unless the file lands in an already-globbed `dir/*.cpp`.

WORKFLOW GOTCHA — **the git-ignored engine cache (`docker/engine/cache/godot`) is volatile**: editing files there in-place had a subset of edits silently reverted mid-session (a hook or concurrent teammate agent). Reliable method to produce engine patches: copy the WARM (post-prior-patch) files to a scratch WORK mirror, edit the WORK copies (immune), generate patches via `diff -u warm work` with rewritten `a/…`/`b/…` headers, then momentarily restore the cache to warm and `git apply --check`. The durable deliverables are the patch files under `docker/engine/patches/` (git-tracked), not the cache. Also: `scripts/build.sh` (OUTER wrapper) must forward new `versions.env` knobs into the `docker run -e` list — build-engine.sh (inner) reading the knob is not enough (same class as the mimalloc-FIT baked-knob trap [[voxiverse-mimalloc-fit-build]]).
