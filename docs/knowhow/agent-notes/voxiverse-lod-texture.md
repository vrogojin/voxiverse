User asked (2026-07-23) for multilevel LOD terrain: from FAR low-detail (smooth downscaled texture, "few thousand blocks" coarsest) resolving progressively to full blocks on approach; each facet's fidelity texture computed by DOWNSCALING THE REAL IMAGE formed by the assembly of that facet's surface blocks. Workflow: Fable research/design → Opus implement/test → Fable assess/debug. Ship live if headless-validates.

**User's 4 LOCKED decisions (AskUserQuestion):** (1) smooth texture far → sharpens to blocks progressively; (2) far textures MUST reflect player edits (costlier re-bake path chosen); (3) push LOD live if headless-validates; (4) many crossfaded tiers, seamless.

**Design DONE (Fable) → docs/COSMOS-LOD-TEXTURE-DESIGN.md (committed deploy/perf-plus-sky @ 79f4185).** Key architecture:
- Bake technique = **CPU composite from the C++ `sample_columns` sampler + edit overlay → `Image.resize` downscale** (NOT SubViewport RTT — you can't photograph unmeshed facets; RTT needs GPU readback stall; CPU composite is deterministic/headless-gateable and IS "downscale the real block image"). sample_columns colors = FarPalette.color_for = BlockCatalog.color_of the real top block (one-sampler law).
- Layout = **Texture2DArray, 6 face pages 384² (BASE_TEXELS=16/facet edge)** → within-cube-face bilinear filtering makes ~99% of facet seams free (only 12 cube edges are boundaries, agree via worldgen continuity). Close-up tier = 2nd array, 64 layers 128², LRU by angular distance.
- **Crossfade = per-fragment albedo blend INSIDE one opaque material** (mix vertex-color↔base-map by wt=smoothstep(600,1800,cam_dist); base↔closeup by wc), NOT alpha-blended co-resident tiers (rejected: pops + WebGL2 sorting/double-fill). Honors the locked seamless law. Extends _SHELL_ABS_SHADER; far ring stays ONE draw.
- Riding the existing FacetFarRing (already meshes whole globe as 1 draw; its CELLS=4 per-block color is the resolution problem the texture fixes). UV emission threaded through the ring's cache builders (§1.3 touch points).
- Edit re-bake: invalidate at _write_cell (world_manager.gd:1242) / sim_revert_cell (:1264), fid via FacetAtlas.edit_key_fid; bounded BAKE_BUDGET_MS=2.0, debounce REBAKE_MIN_S=1.0; single block is sub-texel (averages out) — structures ≥~2 texels show.
- NEVER-OOM: ~18.8 MB all-flags-on (FACET_TEX_BYTES_MAX=20; base-tier-only ~8.2 MB), fixed-size buffers, wholesale-clear on breach, close-up LRU evicts only outside-cap facets (base map never evicted = safe floor).
- **Flags** (each requires the prior, byte-identical off): FP_FACET_TEX (base map) → FP_FACET_TEX_CLOSEUP → FP_FACET_TEX_EDITS.
- **5 phases**, each headless-gated (verify_facet_tex.gd G-FT-*). Phase 5 = live A/B + flip on.
- **R6 = the ONE live-only risk**: sampler2DArray + RenderingServer.texture_2d_update(layer) on gl_compat/ANGLE must be live-smoke-tested; single-ImageTexture fallback fully specified. Must smoke in Phase 1 before Phases 2-4 build on the array path.
- Disclosed: single-block edits sub-texel from orbit by construction (honest downscale); if per-single-block orbital visibility wanted → separate decal feature.

**USER HARD REQUIREMENT 2026-07-23 (top invariant for ALL LOD/tier work):** "ensure correct terrain fidelity gets rendered and NOT seeing any low-fidelity terrain PROTRUSION through the terrain." I.e. the coarse/far tier geometry (far-ring backstop CELLS=4, ~104-block chords) must NEVER poke up through the fine near terrain — it linearly chords between sparse samples so in CONCAVE regions (valleys between samples) its surface exceeds the real fine terrain → protrudes. Must be GUARANTEED away (gated, falsifiable), not just reduced, BEFORE adding higher-res tiers (a sharper texture over poke-through geometry makes it worse). Mechanisms: sink (skin 1.5 / backstop 16) must be ≥ max chord-error; covered-tile/bubble-mask skip (don't emit far where near covers); One-Surface Law; see [[voxiverse-tier-depth-priority]] + docs/COSMOS-TIER-DEPTH-PRIORITY-DESIGN.md + FP_TIER_* flags. The texture crossfade is albedo-only (no geometry) so it doesn't add poke-through — the GEOMETRY tier composition is what must be depth-correct. Gate: sample many columns, assert coarse-tier surface ≤ fine-tier surface (minus margin) OR not-emitted-where-covered, across concave/valley terrain.

**WebGPU migration = DEAD END for the goal (2026-07-23):** real WebGPU+compute on web NOT achievable — wgpu's WebGPU backend is wasm-bindgen/wasm32-unknown-unknown-only and DISABLED on emscripten (which Godot's C++ web build requires); emdawnwebgpu exists emscripten-side but wgpu can't consume it. davnotdev fork on web = wgpu-on-WebGL2 (no compute). So fidelity MUST come from the WebGL2/gl_compat stack. See [[voxiverse-godot-migration]].
