After the FP-M2 controller-fix live test (2026-07-15), the user gave two design directions plus a measurement note. Under investigation by team agents at time of writing.

**1. Neighbour LOD blocks look UGLY + don't coincide with the high-res blocks → generate neighbouring facets NORMALLY (full-res).** The FP-M2 LOD-neighbours system (FacetLodMesher: non-imminent facets become screen-space-error blocky meshes off the voxel pool, for generation throughput) produces visibly coarse blocks at neighbour faces that don't line up with the active facet's full-res blocks at the seam. User wants neighbours rendered as normal generated terrain, not LOD decimations. NOTE: this partially reverses the FP-M2 throughput approach — must weigh against the reason FP-M2 exists (generation-throughput ceiling + NEVER-OOM). Investigate before implementing.

**2. Underground generation optimization to speed INITIAL blocky near-terrain gen:** skip generating the underground entirely, OR just fill it with stone blocks; then re-generate underground GRADUALLY + LAZILY — only underground areas about to be exposed very soon (near a dig/break, near-surface) get real generation promptly; deeper/other underground zones regenerate slowly in the background. Goal: near-surface terrain streams in fast, underground detail fills in on demand.

**3. Measurement gap:** `worst_ms` in the remote telemetry is censored at a 50 ms cap (both pre/post-fix sessions saturate it → crossing frame-time improvement is unmeasurable). Being lifted (emit raw per-frame max) + redeploy so crossing spikes become quantifiable.

**Why:** the controller-fix delivered residency + pre-warm but the crossing/walking hitch (~24 fps, worst_ms pinned 50) persists — that is [[voxiverse-crossing-phys-spike]] / #114 (redesignate's PlanetRoot transform re-placing all mesh blocks), the dominant remaining hitch, now the next target. Related: [[voxiverse-faceted-planet]], [[voxiverse-never-oom-web]], [[voxiverse-web-time-process-invalid]], [[voxiverse-remote-telemetry-launch]].

**UPDATE 2026-07-16 — user hardened the direction into 4 explicit directives (after seam-polish PR#18 merged; crossing STILL jerky/immersion-breaking):**
1. **REMOVE low-res block generation TOTALLY** — "looks ugly, adds no value." Not just polish the LOD (seam polish did that) — DELETE the coarse-LOD neighbour generation entirely (FacetLodMesher/FacetLodBuilder low-res tiers + far-ring quads). This SUPERSEDES the FP-M2 LOD system + the just-merged seam polish (both become moot under the new render model).
2. **Render distance = 256 blocks for the CURRENT facet + 256 blocks for NEIGHBOUR facets** — full-res only. **CORRECTED by user 2026-07-16: beyond 256 = the EXISTING FAR terrain rendering (distant blocky hills blending into low-res far-horizon), NOT fog.** So the render stack = full-res near (current+neighbours to 256) → [REMOVE intermediate near-neighbour FacetLodMesher LOD ℓ1/ℓ2/ℓ3 — the ugly close ones that don't coincide with the full-res seam] → far terrain / far-ring (distant horizon, STAYS). Distant-planet vista PRESERVED via far terrain. "Remove low-res block generation" = remove the intermediate FacetLodMesher near-LOD only, NOT the far-ring/FarTerrain distant horizon.
3. **Mesh + collision CACHE:** once a voxel mesh (INCLUDING its collision structure) is generated, cache it in memory and NEVER regenerate. Cache key = facet/chunk; invalidate on edit (sparse _edits overlay); NEVER-OOM eviction. This is the core fix for re-cross regeneration jerkiness.
4. **Investigate residual jerkiness with PARALLEL team agents** (launched 2026-07-16: jerk-generation, jerk-meshcollision, jerk-poolframe — 3 angles: gen-throughput / mesh+collision-rebuild / pool+frame+deferred-spikes). Synthesize → design → implement, flag-gated, own branch off main (separate from orbital feat/voxiverse-orbital). Note the 167–345ms deferred-spike + 2-worker web gen ceiling from prior work are the prime suspects.

- **THE CORE ISSUE (user 2026-07-16): GENERATION is too slow + inefficient.** Symptoms: mid-facet walk jerky, crossing freezes secs, running fast → fall through ungenerated ground. User's incisive question: "why bother with curved world? each facet is a flat mesh." ANSWER: terrain is a 3D sphere-field sampled per column (~8× noise3d + f64 fold) FOR CROSS-SEAM CONTINUITY (independent flat 2D-per-facet would crack at every ridge). Found inefficiencies: (1) worker recomputes column_profile ~11× per column (pcache fresh per _generate_block; ~180-deep column spans ~11 vertical 16³ blocks; analytic path already has a persistent memo, worker path doesn't — terrain_config.gd:876-896 vs module_world.gd:2622); (2) underground over-generated per-voxel (never meshed/seen). **gen-efficiency agent profiling 3 fixes:** (A) bulk underground stone-fill (user pre-accepted stone-fill+lazy regen), (B) persistent per-worker column memo (thread-safety hard), (C) user's 2D-face-local noise — continuous WITHIN a face across facet ridges, seams only at the 12 cube edges, much cheaper, but per-face terrain + cube-edge seams (terrain-change tradeoff for user). Awaiting data-backed plan → review → implement. FP_FULLRES_256 (widen to 256) HELD as a measured A/B AFTER gen is fast enough (else 256's 4× volume makes it worse).

**MEASURED COST MODEL (gen-efficiency microbench N=40k, docs/COSMOS-GEN-EFFICIENCY-DESIGN.md) — OVERTURNS the curved-world assumption:** per 319µs land column: column_profile (the "curved" sphere-field math) = **~2%** (2.29µs/col); slope_run ~1.6%; **underground resolve_cell = ~76%** (84 cells×2.9µs=244µs); surface ~22%. A fully-underground 16³ block = ~13.7ms (4096×resolve_cell); a crossing restreams ~500 → ~3.4s on 2 workers = THE freeze + fall-through. **The invisible underground eats the whole gen budget — NOT the sphere math.** So Fix C (2D face-local) is perf-NEUTRAL (measured 1.82 vs 1.87µs/col ≈ 0.02%; get_noise_2d≈get_noise_3d) → I owned that my earlier "curved world is the bottleneck" framing was WRONG. **USER DECISION 2026-07-16: Fix A (bulk-underground) ONLY, drop Fix C** (perf-neutral terrain change not worth it). **Fix A = THE lever:** bulk-fill provably-interior underground blocks via VoxelBuffer.fill (STONE ≥-16 / DEEPSLATE ≤-24; guards: s==1, faceted ridge-interior, oy+16≤min_h−12) → 13.7ms→0.5ms (~27×), freeze→sub-second, stops fall-through. Physics-safe (block_id_at→resolve_cell reads TerrainConfig DIRECTLY not the mesh → drops/collision always true; only unexposed-underground APPEARANCE = plain stone until dug). Flag FP_BULK_UNDERGROUND (off→byte-identical). Exposure = A-lazy (regen block per-cell on first dig; fallback A-accept). impl-bulk-underground agent building → gate (FLAT 6035/0 off + truth gate: exposed==resolve_cell + block_id_at unchanged + no-fall-through) → deploy. Fix B (worker memo) SKIP (<1%, mooted).
