**TWO DISCREPANCIES the kernel agent surfaced (must resolve at O1 LIVE-WIRING; both = doc's post-O3 assumptions vs today's R=3072 planet):**
1. **R_body mismatch (the big one):** gravity_fixed/altitude use `radius_of("earth")=6371` (the POST-O3 resize value), but the live planet is still `FacetAtlas.R_BLOCKS=3072`. So near the ground `h=|p|−R` goes deeply negative (3072−6371=−3299) → the blend band [128,512] is unreachable, FLY→ORBITAL latch would sit ~3800 blocks above a 3072 surface. ⇒ O1 live-wiring has a HARD dependency on O3 (resize) landing first, OR gravity_fixed must be fed the ACTUAL planet R (FacetAtlas.R_BLOCKS today / r_of post-O4a) instead of the ephemeris 6371. Documented in cosmos_gravity.gd header.
2. **Drag K0 tuned to feel_g but integrator uses Newton g:** K0=feel_g(22)/DRAG_TERMINAL² gives 55 m/s terminal ONLY if surface g==22, but the ACTIVE integrator's gm/r²=50.9 at r=6371 → real re-entry terminal ≈83.7 m/s (>the design's ≤55-60 streaming budget; commit window 6.1s vs stated 8.5s). Fix: retune K0 to Newton surface gravity (connects to D-O4-5 airless-landing pacing). Kernel matches the doc; the doc's promised number won't hold end-to-end.
Neither blocks anything shipped (kernels gated off, not wired live). Both resolvable by Opus at impl time but connect to user decisions (O3 timing, landing pacing).
