Fable design (docs/COSMOS-ORBITAL-SHELL-DESIGN.md, committed b539d12): the "far side of the planet renders no terrain from orbit" bug is a POLICY bug, NOT a missing representation.

**Key fact:** `godot/src/world/facet_far_ring.gd` is ALREADY one merged single-draw-call coarse mesh of the ENTIRE globe (all 3456 facets = K=24 per cube-face edge × 6 faces; heights from `TerrainConfig.profile_at_dir`, colors from FarPalette/BlockCatalog, persists to any altitude via SN3/CosmosScale clamp). It just only EMITS the hemisphere around the player's ACTIVE FACET (`_front_visible` culls vs `facet_normal64(_active_fid)`, ~facet_far_ring.gd:291-302) and refreshes that set only on surface-crossing events. Off-surface the radial dir drifts across facets with no crossing → emitted hemisphere stays pinned near departure → far side literally absent.

**Fix (S1 FP_SHELL_CAMERA_SET):** cull axis = CAMERA radial dir with altitude cap θ_emit=min(arccos(R/d)+8°+15°, 96°), re-emit on >13° sub-camera drift, reuse existing emit/build/swap machinery. θ_emit≥90° floor below OFFSURFACE_Y keeps surface byte-visually identical. ONE draw call, ≤~7.3MB GPU worst / 2.4MB CPU cache ceiling (NEVER-OOM clean; low orbit ~3× CHEAPER than today). No cross-fade needed — set changes are invisible BY GEOMETRY (facets enter/leave only behind the limb; 15° slack guarantees it). **S2 FP_SHELL_PREWARM** = one-shot whole-planet cache warm above OFFSURFACE_Y (kills first-pass warm lag). User chose S1+S2. Implemented on feat/voxiverse-shell (agent impl-shell).

Deps: above h≈6.3k the fixed 9000 camera far clips the limb — owned by SN3 [[voxiverse-scaled-body]]/FP_SCALED_BODY far ramp, not shell work. Rejected: per-facet nodes (3456 draws), a 2nd globe mesh (drift seam + double bytes). Indexed full-sphere build (~4.8MB, zero rebuilds) kept as pre-approved fallback if S1 re-emit churn fails soak. Ties to [[voxiverse-seamless-scales]] (overlap-not-fade, honored), [[voxiverse-faceted-planet]], [[voxiverse-never-oom-web]].

**S1b LIVE FIX (2026-07-18, committed f869bba) — the headless gates passed but the far side stayed blank in a real orbit.** LESSON: the S1 gates drove `shell_set_camera_abs` + `force_rebuild` DIRECTLY, which bypasses `_warm_front` — they never exercised the live `driver→_warm_front→_process→emit` chain. Root cause: `_process` only fires `_begin_rebuild()` when `_warm_front()` returns true = EVERY front-cap facet cached in ONE WARM_BUDGET_MS (3 ms) frame. Surface crosses facet-by-facet (cap stays warm, passes); ORBIT exposes ~700-1900 never-visited facets at once, and on web (×25 profile cost) that can't cache in one 3 ms frame → `_warm_front` never true → `_begin_rebuild` never fires post-ascent → emitted set FROZEN on the ascent hemisphere. Fix: true-orbit path emits the CACHED SUBSET each rebuild (`visible_fids(cached_only)` filters), grows it as warm+prewarm fill (`SHELL_REEMIT_GROWTH`=64), keeps surface/flag-off all-or-nothing (byte-identical). Added `shell_telemetry()` (sh_emit/sh_visN/sh_cachedN/sh_begin/sh_wfail — H-A; cam_far vs limb tangent √(d²−R²) — H-B far-plane; sh_axdot — H-C) + gate G-SHELL-LIVE (drives real apply_camera_set→_process, converges cold antipode cap; fails old, passes new). Awaiting live telemetry to confirm H-A closed vs reveal H-B. **Rule: any flag whose live path runs through a per-frame warm/budget gate needs a gate that steps _process, not just force_rebuild.**

**ACTUAL ROOT CAUSE (2026-07-18, telemetry-confirmed, committed 0b2a934) — the far side stayed blank because the shell DRIVER never ran live, not the warm/emit chain (S1b was correct but unreachable).** `main.gd _process` returns early at `if CubeSphere.FLAT_WORLD or _player == null: return`, and the FACETED production game ships **FLAT_WORLD=true** (a facet IS a flat world — cube_sphere.gd requires it). The shell hook + the SN3 `apply_scaled_body` hook both sat AFTER that return → dead live (telemetry: `shell_telemetry()` = {} every frame). Fix: move the shell driver ABOVE the return, beside the sky clock (which is deliberately pre-return for the same reason). SCALED-BODY left dead: at low orbit the shipped faceted camera far=9000 (player.gd:193) already reaches the far-ring limb √(d²−R²) (< 9000 until h≈6438), so the driver-move alone renders the far side; FP_SCALED_BODY far-ramp only matters above h≈6.4k (separate pass). Gate G-SHELL-DRIVER-REACHABLE asserts (source-order) the driver call precedes the FLAT_WORLD return in _process. Also added a NavHUD velocity readout (|v_bci| + v_circ=√(GM_dyn/r), SN_HUD_NAV). **LESSON (bites twice now): direct-call/unit gates that construct a subsystem and call its methods CANNOT catch a dead main-loop hook — a production driver hook needs a gate that checks main._process actually reaches it under the SHIPPED config (esp. FLAT_WORLD=true). Both faceted-shell bugs were "the code is correct but never called live."**

**S1c — THE ACTUAL LIVE ROOT CAUSE (2026-07-18, telemetry-proven).** S1b still didn't render the far side live. Captured telemetry showed `shell_telemetry()` = {} EVERY frame across the whole fly ⇒ `_cam_set` never engaged ⇒ `apply_camera_set` never called. Cause: the shell per-frame DRIVER hook in `main.gd _process` sits at ~line 194, AFTER the early-return at line 162 `if CubeSphere.FLAT_WORLD or _player == null: return`. **FLAT_WORLD is committed TRUE — it is the PRODUCTION config (walking game always ships FLAT_WORLD=true; it is NOT in any deploy flag list).** So `_process` returns before the shell hook: `update_shell_camera_set(cam)` runs ZERO times live. The sky clock (lines 159-161) is deliberately placed BEFORE the return; the shell hook (and the SN3 `apply_scaled_body` hook at ~184-188) were placed AFTER it → **both are DEAD live**. FP_SCALED_BODY has therefore likely never run live either (matters for the shell high-altitude limb clip; S1 is standalone-correct at low orbit). Orbit-decay fix was unaffected because it lives in `player._physics_process`. Gates missed it because they drove `apply_camera_set`/`_process` on the ring DIRECTLY, bypassing `main._process` + the FLAT_WORLD guard. FIX (agent impl-shell): move the shell driver (and assess scaled-body) above the FLAT_WORLD return (guard `_player==null`, compute `cam` there) + a gate that drives the REAL main._process. **RULE: a per-frame driver hook in main._process placed after the `FLAT_WORLD` early-return is DEAD in production — put cosmos/shell/scaled-body drivers BEFORE line 162 like the sky clock, and gate them by driving main._process, not the subsystem directly.** Also folding a velocity HUD (|v_bci| blocks/s + altitude + v_circ ref) into SN_HUD_NAV per user request. **S1d — sub-camera hole in orbit (2026-07-19, committed 6b07c24).** After the driver fix the far side rendered (telemetry sh_cam=true, sh_prewarm=3456, sh_emit≈sh_visN−5), but the facets DIRECTLY UNDER the player flickered out. Cause: the far ring EXCLUDES the active facet (+ neighbours) / draws them as SUNK FULL_COVER backstops — a SURFACE assumption (near voxels cover the facet you stand on). In orbit the near voxel field is at the player's FLIGHT altitude (h≈819), NOT on the ground under the camera, so the excluded/sunk sub-camera facet is a HOLE that sweeps as the active facet churns (~1 facet/3 frames along the ground-track). Fix: a regime helper `_shell_orbit()` = `_cam_set and not _emit_floored_last`; off-surface the SHELL owns the sub-camera facet — `_front_visible` stops skipping active/`_excluded`, `_is_backstop` returns false (regular coarse, prewarm-filled ⇒ no warm hole, un-sunk), and `set_active` skips `_pending` (the emit is camera-axis-driven + mesh is absolute ⇒ a crossing doesn't change the set ⇒ kills the redundant full rebuild every ~3 frames = the sh_reemit≈690 churn). Surface/flag-off (`_shell_orbit()` false) = shipped, byte-identical. Gate G-SHELL-SUBCAM (off-surface active+neighbours emitted & un-sunk; on-surface excluded). Coarse (CELLS=4) under the camera — sharper = design S3 FP_SHELL_DENSE_CAP follow-up. **LESSON: any "near field covers this, so the far tier can skip/sink it" assumption is FALSE off-surface (near field is at flight altitude, not on the ground) — regime-gate every surface-coverage assumption on `_shell_orbit()`.** verify_shell 39/0, FLAT 6035/0, faceted/fixed_frame/farring_cover(FULL_COVER 14/0)/tier_depth/skin all green.
