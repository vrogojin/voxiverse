VOXIVERSE = a Minecraft-like highly-detailed voxel *immersive simulation engine* built in Godot, served as a browser (Web/HTML5) game. Repo: `~/voxiverse` (was empty; scaffolded 2026-07-02). GitHub: personal account `vrogojin` (SSH).

**First deliverable (test env):** basic first-person voxel game — static, unbreakable, infinitely procedurally-generated flat grid of grass blocks; simple hilly terrain (FastNoiseLite); air/env temperature 21.5 °C; procedurally-generated 64×64 grass texture applied to the grass material; render radius 256 blocks then fog; scene lit by ambient/omnidirectional light (no sun/shadows). Always-on HUD thermometer showing Air temp (head block) and Ground temp (block under player). "FPS" = first-person controller + a look-at interaction ray to probe voxels.

**Locked build decisions (2026-07-02, user going in-depth then to bed, full autonomy granted):**
- Scope: ship the playable demo AND begin the deeper sim systems (voxel material/state model, per-voxel environment framework).
- Engine tech: **Godot 4.4 + Zylann `godot_voxel` C++ module** — requires building a custom Godot web engine + export templates in Docker (long pole; keep a GDScript-chunk fallback so the web demo always ships).
- Ground temp: derive from a **simple per-voxel environment model** (surface/depth/light) — real groundwork for the VOXIVERSE environment system, not a hardcoded constant.
- Deploy: **auto-deploy live** to `voxiverse.game-host.org` (DNS → <deploy-host-ip>), fully autonomous overnight.
- Budget: **aggressive** — large multi-agent effort, adversarial self-review, iterate until polished.
- GitHub: create repo + push branch.

**Serving path:** Godot Web export served by a container that terminates its own TLS and self-registers with haproxy. haproxy at `~/haproxy` uses **SNI SSL-passthrough + ssl-manager autossl** (container sets `HAPROXY_HOST=haproxy`, `SSL_DOMAIN=voxiverse.game-host.org`, joins `haproxy-net`). Godot 4 web threading needs cross-origin isolation → server MUST send `Cross-Origin-Opener-Policy: same-origin` + `Cross-Origin-Embedder-Policy: require-corp`.

**Game impl status (2026-07-02, Stream B):** Godot 4.4 project built under `godot/` (GL Compatibility renderer). Scene assembled in code from `scenes/main.tscn` → `src/main.gd`. Both rendering paths wired and selected at runtime via `ClassDB.class_exists("VoxelTerrain")`: the `godot_voxel` module path (`src/world/voxel_module/module_world.gd`, kept parse-clean without the module by driving it through ClassDB + a runtime-compiled `VoxelGeneratorScript`) and the **pure-GDScript fallback** (`src/world/fallback/chunk_mesher.gd` greedy heightmap mesher + `chunk_streamer.gd`). Shared world shape lives in `src/world/terrain_config.gd` (`height_at`/`is_solid`) — consumed by both meshers, the player's analytic floor/raycast, and the sim. Sim layer decoupled in `src/sim/` (`VoxelMaterialDef`/`VoxelState`/`VoxelStateTransition` state machine + `PerVoxelEnvironment`). Ground-temp formula (documented in `docs/SIM-MODEL.md`): air=21.5 °C; solid `T = 12.0 + (23.0-12.0)*exp(-depth/4.0)`.

**Validated end-to-end with real Godot 4.4** (downloaded stock binary, no module): all GDScript compiles, scene runs headless with zero errors (selects fallback), mesher emits geometry, temp model returns 21.5/23.0/12.07, and a real **web export via the "Web" preset succeeds** (index.html/wasm/pck, threads/SharedArrayBuffer enabled → confirms COOP/COEP serving requirement). NOTE: Godot 4.4 treats "type inferred from Variant" as a compile ERROR — use explicit types / `floorf` / `: Object` for `ClassDB.instantiate`. `grass.png` is a committed asset; `.godot/` and `build/` are gitignored; export/import needs a `godot --headless --import` pass before `--export-release`.

**Web module-path fix (2026-07-03, Stream B):** The live web build runs the godot_voxel MODULE path (Stream A's web template includes it; selected via `ClassDB.class_exists("VoxelTerrain")`). Two bugs made the world render blank: (1) **pthread-pool exhaustion** — godot_voxel's VoxelEngine sized its task pool from CPU count, spawning more threads than Emscripten's fixed web pool → meshing deadlocked. Fixed by pinning to 1 thread via `project.godot` `[voxel] threads/count/minimum=1, ratio_over_max=0.0, margin_below_max=0`. (2) **id/material bug** in `module_world.gd` — original used a nonexistent `set_model` and never added an air model, so grass landed at id 0 (=air). Fixed for godot_voxel **v1.4.1** API: `VoxelBlockyLibrary` starts empty, `add_model(VoxelBlockyModelEmpty)`→id 0 (air), `add_model(VoxelBlockyModelCube)`→id 1 (grass) with `set_material_override(0, mat)`; generator injects that id and overrides `_get_used_channels_mask()` (CHANNEL_TYPE=0). Validated headless with the module binary at 1 thread: `is_area_meshed=true` in ~1s and voxel read-back = grass(1) below surface / air(0) above. Re-exported `build/web` (regenerate `.gz` variants after export — export only refreshes raw files, stale `.gz` would otherwise be served). Probe the module binary via `docker run --entrypoint /bin/bash voxiverse/godot-build:4.4 ... godot --headless -s res://probe.gd` to introspect the godot_voxel API.

**Physics sandbox + block breaking (2026-07-03):** Terrain flattened to shallow rolling hills (`terrain_config.gd`: dropped the mountain mask/ridge; BASE 5 / HILLS_AMPLITUDE 3 / DETAIL 1 → heights ~2–9, all below the snowline so the world is uniform grass; `VIEWER_VERTICAL_RATIO`→1.0). Added real physics: `src/physics/voxel_body.gd` (RigidBody3D cluster of voxel cells; exposed-face mesh + per-cell BoxShape + mass; `break_cell` removes a cell, recomputes 6-neighbour connected components and spawns each detached component as its own dynamic body — pristine pillars spawn FROZEN/STATIC so thin stacks stand, first break "activates" ungrounded pieces to fall/tumble/be pushed) and `src/physics/ground_collider.gd` (single `ConcavePolygonShape3D` trimesh of the blocky surface over a 28-block region around the player, rebuilt on move + on edit; the ONLY terrain collision since both render paths are collider-less). `src/world/wood_material.gd` bakes a runtime procedural wood texture (no PNG import). Left-click breaks the pointed-at block within `break_reach`=4 m: physics ray (wood) vs analytic voxel DDA (terrain), nearest wins; player also shoves dynamic blocks it walks into. Terrain breaking = a removed-cell overlay in `WorldManager` (`_removed`, `is_removed`, `effective_height`, `break_terrain`): gameplay truth for `surface_y` (scans down → fall to next block, never hollow since columns are solid downward) and `aimed_voxel` (skips removed); mirrored into the live godot_voxel path via `VoxelTool.set_voxel(cell,0)` (`module_world.remove_voxel`) and into the fallback via effective-height remesh (`ChunkMesher.build`/`ChunkStreamer.remesh_cell` take the WorldManager). Collision layers: 1=ground, 2=wood bodies, 4=player capsule. Verified headless on the MODULE binary (`docker/engine/bin/godot.linuxbsd.editor.x86_64`, has VoxelTerrain/VoxelTool): overlay math, VoxelBody split, live VoxelTool carve read-back (grass1→air0), and a real detached piece falling 1 block onto the ground collider. NOT yet re-exported/deployed. Known limitation: player movement is analytic so it clips through standing (frozen) pillars — only dynamic pieces are physically pushed.

**Physics polish round (2026-07-03, 2-agent team + integrator):** (1) Aim highlight — `src/player/aim_highlight.gd` (`AimHighlight`, a world-space `top_level` wireframe-LINES cube, unshaded + `no_depth_test`) marks the block the player would break; `player._current_target()` refactors the "nearest of physics-wood-ray vs analytic-terrain-DDA" targeting so highlight and break agree, and it follows a tumbling body via `body.global_transform * Transform3D(Basis(), Vector3(cell))`. (2) Detached-piece stability + distinct look (`voxel_body.gd`): dynamic pieces get `angular_damp=4`, `linear_damp=0.1`, a shared no-bounce friction-0.5 `physics_material_override`; each dynamic body swaps to `WoodMaterial.build_variant(idx)` (golden-ratio hue/brightness tint off a static counter) so loose pieces are visually distinct from standing pillars and each other. (3) Mass-based push: `BLOCK_MASS` 20→12 kg; `player.push_force=1200 N` applied as `apply_central_impulse(dir*push_force*delta)` (NO mass multiply → accel=F/m, so mass matters) gated by `linear_velocity.dot(dir) < move_speed` (light block rides along at walk speed, heavy pile creeps). Verified: 12 kg → 5.7 m, 96 kg → 0.07 m.
**Then fixed 3 movement/collision bugs:** (a) player now collides with wooden blocks — horizontal move goes through `move_and_collide` (+1 slide) with the player's collision_mask = wood-only (layer 4, mask 2), so pillars are solid and loose pieces block-then-get-shoved; terrain stays analytic. (b) `WorldManager.floor_under(x,z,feet_y)` scans DOWN from the feet (with `STEP_UP=1.1` for ~1-block step-ups) for the first solid non-removed block, replacing the column-top `surface_y` as the PLAYER's floor — so you can descend dug shafts/pits and walk INTO tunnels instead of being teleported back to the original surface (`surface_y` still used for spawns/grounded test). (c) **Detached pieces were falling THROUGH the ground** — root cause: the `GroundCollider` was a `ConcavePolygonShape3D` trimesh of thousands of 1×1 quads, which has Godot's "internal-edge" problem (resting bodies slip through triangle seams, flaky). FIX: rewrote `ground_collider.gd` to a single **`HeightMapShape3D`** (65×65 samples of `effective_height+1`, body at integer centre so verts land on columns, rebuilt on 8-block move + on edit) — seam-free, cheap, reliable resting. Trade-off: heightfield interpolates (steps→ramps) but the collider is invisible and terrain is gentle. GOTCHA for future: never use a many-quad trimesh for resting-body ground collision in Godot Physics 3D — use HeightMapShape or convex box-per-column. Re-exported + redeployed live (commit not yet made).

**Hotbar/inventory + multi-material terrain + trees (2026-07-04, Fable-planned 4-agent parallel build + adversarial review):** Big feature round. (1) **`sim/block_catalog.gd` (`BlockCatalog`)** = authoritative id/mass/colour/name table on the VoxelState framework — the single source everyone reads. Materials: air0, grass1(750kg), dirt2(900), stone3(1500=heaviest), wood4(80=lightest), leaf5(100). `world/block_materials.gd` (`BlockMaterials.get_for(id)`) supplies cached render materials (textured grass/wood, solid-colour dirt/stone/leaf). (2) **Layered terrain** in `terrain_config.gd`: `generated_block(x,y,z)` = grass at surface `g`, dirt band, stone from `min(stone_height_at, g-3)` down (never hollow); `stone_height_at` is a SECOND decorrelated FastNoiseLite → stone hills don't coincide with grass and sit ≥3 deeper. (3) **Trees** `world/tree_gen.gd` — deterministic hash-of-position patches (wood trunk + leaf canopy), part of `generated_block` so both render paths + reloads agree; replaced the wooden test pillars; chopping a trunk detaches the canopy as a mixed VoxelBody. (4) **Edit overlay redesign** in `world_manager.gd`: `_edits: Vector3i→id` (0=air,>0=placed) replaces the old `_removed` set; `block_id_at(cell)`=overlay-else-generated is THE cell query; `break_terrain(cell,from_pos)→broken id`, `place_block(cell,id)→bool` (rejects occupied/invalid, mirrors into render path, rebuilds ground collider). (5) **Hotbar/inventory** `ui/inventory.gd` (`Inventory`, RefCounted, Minecraft stacking, 9 slots, max 64) + `ui/hotbar_hud.gd` (`HotbarHUD` CanvasLayer, colour swatches + counts, selected border); 1–9 keys + scroll wheel select; break→`add`, right-click→`place_block`+`consume_selected`. (6) **Surface-FACE highlight** replaced the wireframe cube (`aim_highlight.gd` `show_face`: unit quad on the aimed face, additive white, depth-test ON for occlusion). (7) **Physics** `voxel_body.gd`: `cells` now `Vector3i→id`, mass summed from catalog, per-id mesh surfaces (no more wood tinting), detach kick AWAY from breaker on pickup (`DETACH_KICK_SPEED`), and **settle-freeze** — a ground body (no wood) re-freezes to STATIC once grounded & at rest so a lone dirt block can't be pushed/tipped/jumped-off; re-drops if support later dug out. Adversarial review (Opus) found + I fixed: `_grounded()` only checked terrain heightmap → soil-on-soil / soil-on-placed-tower never froze; now also does a downward physics probe onto the static ground collider or a frozen body (frozen-body re-check throttled every 12 frames). Verified headless on the module binary: `src/tools/verify_feature.gd` (committed regression test) = 14478 assertions pass; a physics-stepping probe proved stacked dirt freezes with 0.00 m drift under a 6700 N impulse.
