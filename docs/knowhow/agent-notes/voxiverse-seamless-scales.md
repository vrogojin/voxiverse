**LOCKED USER REQUIREMENT (verbatim intent, 2026-07-17):** *"walking, flying within the atmosphere, orbiting in the planet vicinity, all should be natural and smooth. **No stitches and jumps** when crossing facets and when crossing the atmosphere-space border as well (we might consider even **rendering the surface blocks from space** wherever applicable)."*

This is a **continuum** requirement, not a per-tier one: the player must be able to walk → fly → orbit → return with no visible pop, tier swap, or discontinuity anywhere along the path. It binds the render stack, the streaming scheduler, AND the orbital design together.

**⚠️ IT CONFLICTS WITH THE SHIPPED O1 DESIGN.** `docs/COSMOS-ORBITAL-O1O4-DESIGN.md` §2.8 specifies **H_FARSWAP = 20000**: above it, *retire the live pool AND the far ring*, and render the home body as a **sphere impostor**; on descent, rebuild the far ring ("the veil is acceptable v1 — measured"). That is precisely a stitch/jump at the atmosphere-space border. **The "acceptable veil" v1 is now REJECTED by this requirement** and the border must be redesigned as a continuous blend (or the tiers made cheap enough to overlap). Same for the O4c SOI/dominant-body swap (designed as "imperceptible" only because nothing voxel-scale exists above H_FARSWAP — that reasoning dies if surface detail must remain visible from space).

**Tier stack that must blend seamlessly (today):** full-res voxels (near, 128 active / 96 neighbour) → [intermediate near-LOD REMOVED as ugly, user's call — do NOT resurrect] → `FacetFarRing` coarse whole-planet horizon (+ `FP_FARRING_FULL_COVER` sunk backstop) → (planned) R3 heightfield skin tier for the 128-256 annulus → (planned) body impostor above H_FARSWAP. **Hard user constraint from the same session: MUST visually cover 256 blocks around the player, fast.**

**"Render surface blocks from space wherever applicable"** — the user is open to real blocky surface detail remaining visible from orbit where it makes sense, rather than a smooth impostor hiding it. Implies the tier selection should be driven by **apparent/angular size**, not just radial altitude, and that the impostor should be a fallback for genuinely sub-pixel detail — not a hard altitude switch.

**Why L5 (C++ generator port) is the enabler, not a detour:** every tier samples the SAME worldgen (`facet_profile`/`column_profile`/`resolve_cell`). At the measured web ×25 interpreter tax, overlapping tiers are unaffordable, so the design reached for hard swaps (H_FARSWAP retire, veils) — which is what creates the stitches. Post-port (supply ~30 → 300+ blocks/s; a skin tile ~60 ms → ~2-3 ms) tiers can **overlap and cross-fade** instead of swapping. **Corollary for the port's interface: coarse/strided/profile-only sampling must be the SAME function as the full sample (a stride/LOD parameter), never a second implementation that can drift** — two implementations = guaranteed seam. See [[voxiverse-gen-class-costs]], [[voxiverse-streaming-supply-demand]], [[voxiverse-orbital-o1o4-staging]], [[voxiverse-faceted-planet]].

**⚠️ SKIN TIER PITCH-1 IS PERF-NEUTRAL — LANDED BUT LEFT OFF LIVE (paired A/B, 2026-07-17 PM, real laptop, post-browser-restart clean thermal state).** The skin overdraw fix (`FP_SKIN_TIER` covered-tile skip via `module_world.skin_near_meshed`→godot_voxel `is_area_meshed`, commit 71fb930 on deploy/perf-plus-sky) works: same short reload-first stand/walk/stand route, back-to-back, skin ON vs OFF = statistically identical (M1 0.49 vs 0.47%, fps p10 55.9 vs 55.7, p50 59.9 both, **draws p50 188 both** ⇒ the skip reaps skin tiles to ~0 net standing/walking). Root-cause of the original ~20fps hit was FILL/overdraw (occluded skin fragments shading behind opaque near voxels on gl_compat — no depth prepass, weak early-z), NOT draws, NOT a material/early-z bug (skin material byte-identical to FacetFarRing's). The fix made the skin genuinely free instead of free-vs-costly — BUT at pitch-1 its unique band is only ~128–138 blocks (byte-capped reach ~138 vs near field 128), too thin to visibly help. **Decision: keep FP_SKIN_TIER OFF live until the pitch-2/4/8 extension rings push reach toward 256, then re-A/B — that's when it earns its keep.** Incidental: each web reload costs a one-time 5.5–6.3s cold-fill boot hitch (initial-fill burst, not gameplay). Live build = the validated freeze-fix state (FP_CPPGEN + FP_INFLIGHT_GATE, skin OFF). Provenance lesson held: strings-checked the exported wasm for `VoxelGeneratorCosmos`/`sample_columns` before trusting the A/B, and reload-first (cache-control:no-cache) guaranteed the right build loaded since telemetry has NO flag marker.

Status: the fixed-frame keystone already made the crossing frame itself cheap (transform_ms=0, crossing_ms 1.7-19 ms) and `FP_FARRING_FULL_COVER` fixed the see-through gap; the residual "slight jerk" the user reported is now understood to be **streaming (supply<demand)**, i.e. the same root cause L5 fixes — not the crossing algebra.
