Root causes for the two live tree bugs (design doc `docs/COSMOS-TREE-BUGS-DESIGN.md`, probes `godot/src/tools/probe_acacia*.gd`, `probe_treechop*.gd`, `probe_gravbox.gd` in the deploy-cheats worktree):

- **Bug 1 (acacia/jungle walk-through, can't break):** the 2026-07-19 overnight batch landed two parallel features that each "appended after the enum end": B1 climate biomes (`B_SAVANNA:=11`, `B_JUNGLE:=12`, terrain_config.gd:303) and O4b Moon (`B_MOON_MARIA:=11`, `B_MOON_HIGHLANDS:=12`, :310). `resolve_cell:1309` routes biome 11/12 into `_moon_cell` → analytic savanna/jungle columns have NO trees + moon strata (mat −1 with MULTI_BODY off), while the C++ mesh gen (no moon branch) draws correct acacia/jungle. Measured: 9,406 acacia + 2,334 jungle mesh-only cells, 0 profile mismatches. TreeGen itself is correct. Fix design: FP_BIOME_SPACE_FIX renumbers moon ids to 21/22/23 via one helper (biome ids never serialized).
- **Bug 2 (cut canopy flips upside down + sinks):** two defects, isolated headlessly. (a) `GRAV_BOX_TANGENTIAL:=320` (world_manager.gd:915, sized 07-15 for ~200-wide facets) never rescaled for R=6371 facets ~500-590 wide → outer ~60% of every facet has NO gravity Area3D → debris get GLOBAL (0,−9.8,0) (measured gdot −0.605, canopy flies off at 49 b/s). (b) collapse-spawned canopy starts 100% inside its own stale GroundCollider tree boxes (rebuild_now is debounced, ground_collider.gd:223) → depenetration tumble (updot 1.0→−0.609 with CORRECT gravity); both together → NaN in one step headless. Fix design: FP_GRAV_BOX_COVER (box from dom_min/dom_max + margin, centred on domain centre — domains are asymmetric about centre_cell) + FP_CHOP_COLLIDER_CARVE (synchronous shape carve before spawn_loose).

**Why:** both verdicts PRE-EXISTING vs the four 08-06 flags (repro with flags at committed false; VoxelBody uses 2-arg surface_y + cell_solid, GroundCollider uses col_profile — none welded/guarded). Gate blind spots that let these ship: verify_cppgen never samples savanna facets and its saw_tree counter only counts legacy species; verify_fixed_frame freezes its debris marker so no gate ever dropped a live body; byte-equality gates run at flag defaults so FP_CLIMATE_BIOMES paths were never compared.

**Chop-lag follow-up (2026-08-07, probe_choplag.gd):** the post-fix "dozens of seconds lag after chopping" = PRE-EXISTING awake-body costs exposed by the fixes making the canopy stay (fix flags add no per-frame cost — measured A/B). Drivers: (1) rebuild⇄wake loop — snowfall's sim_ground_rebuild (world_manager.gd:1828) marks the collider dirty every 0.5 s; with an awake body holding the gate open, full-region rebuilds run back-to-back (gc.update 2-4.7 ms/frame NATIVE) and each rebuild jolts the resting body awake again → 30 s awake vs 2.4 s quiet; (2) felling re-wakes the pile per break → 23.7 s awake, 500-1900 pairs ≈ live phys 5-11 ms wasm; (3) FP_TREEPHYS_BOUND's 8 s deadline NEVER fires for wood bodies (_physics_process disabled for wood, voxel_body.gd:302). Fix design FP_CHOP_DEBRIS_CALM: wood awake-deadline (sleeping=true, not freeze) + sim-dirt lazy debounce. Godot's TIME_PHYSICS_PROCESS monitor is untrustworthy on this threaded build (200 ms/frame readings inside 16 ms frames) — use wall-clock + pair counts.

**Intermittent-sink follow-up (2026-08-07, probe_sink.gd):** after the Bug-2 fixes, ~2-3/12 canopies STILL sink — reproduced headlessly, IDENTICAL geometry to survivors (trunk_dist 2.5, canopy 24-26) ⇒ state/timing-dependent. Root cause: the GroundCollider is the ONLY physical rest surface (terrain is mesh-less/analytic) and is R=14, player-centred, double-buffered, debounce-rebuilt — when a canopy drops while the live shape set doesn't cover its fall column (rebuild mid-flight / stale centre), it FREE-FALLS through analytic terrain (measured v=8.8 accelerating through depth 0) and tunnels below surface. Carve EXONERATED (sinks persist 3/12 with FP_CHOP_COLLIDER_CARVE OFF). Old fly-away bug masked it (body left in 2 s). Fix design FP_LOOSE_BODY_ANALYTIC_FLOOR: hard analytic floor clamp in VoxelBody._integrate_forces (covers wood+non-wood, collider-timing-immune, radial-gravity-correct via -gravity_vector). verify_treechop 36/0 missed it because it fully-builds the collider before chopping + parameterises by distance not build-state; new gate must drop into a mid-build/stale collider.

**How to apply:** when two parallel agents both "append after the end" of a shared enum/id space in the same batch, grep for the collision before merging; when the planet/facet scale changes, sweep every hard-coded spatial constant (the GRAV_BOX comment even documented its stale assumption). Coverage counters in byte-equality gates must include NEW ids or flag-ON runs are vacuous.
