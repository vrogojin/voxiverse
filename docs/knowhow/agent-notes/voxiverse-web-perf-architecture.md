Fable-tier architecture analysis of VOXIVERSE web walk/crossing perf (docs/COSMOS-PERF-ARCHITECTURE-ANALYSIS.md, 2026-07-16). Diagnoses the "much better but not acceptable" jerkiness after the gen fixes ([[voxiverse-neighbour-underground-direction]]). Key mental model + fix plan:

**MEASUREMENT INTEGRITY (critical — most prior data was misread):** only `worst_ms` (true wall ticks_usec delta) + `fps` + `draws`/`prims` are trustworthy. `proc_ms`=TIME_PROCESS is INVALID on threaded web ([[voxiverse-web-time-process-invalid]]). `vox_gen/mesh/main/gpu` are QUEUE DEPTHS not ms — "vox_main≈0" means no pending apply tasks at the sample instant, NOT "apply is free."

**Web fps is a VSYNC LADDER, not a dial:** rAF quantizes to 16.7/33.3/50ms. "Acceptable" is a THRESHOLD problem — get true frame cost <16.7ms → fps DOUBLES (30→60); shaving 5ms without crossing 16.7 buys NOTHING visible. Measured: 44 draws→17-19ms(55-60fps); 204 draws→~30ms(clean 30fps). Slope ~40-60µs/draw of GL-compat per-surface bind/uniform cost through ANGLE→D3D11 (per-DRAW-CALL cost, NOT triangles: prims 137k trivial, no shadows, 720p fill trivial).

**TWO NEW ROOT CAUSES (both ours, both cheap, were hidden inside the "render ceiling" class):**
1. **The post-crossing spike is the FAR-RING RE-EMIT, not generation.** `facet_far_ring.gd:140 _rebuild_full()` runs SYNCHRONOUSLY in one frame after EVERY crossing AND every neighbour spawn/retire (`set_pool_excluded:92` also sets `_pending`): ~1728 front-hemisphere facets ×32 tris via ~332k per-vertex GDScript→C++ SurfaceTool calls + generate_normals over ~55k tris = est 300-700ms. Matches the 157-381ms post_worst (constant across crossings, uncorrelated with blocks_replaced). Fix (L1): per-facet pos/color already cached (`_pos_cache/_col_cache:31-32`) → assemble via append_array + precomputed flat normals (~few ms memcpy). +2-3MB, flag-gateable.
2. **OBSERVER EFFECT:** `remote_bridge.gd:508 _capture_frame_async` does synchronous `get_image()` (WebGL2 glReadPixels = full pipeline stall) + resize + JPEG on the engine thread EVERY 500ms in every authed remote session → a ~35ms hitch 2×/sec, load-independent (telemetry shows perfect 2-window alternation 32↔65ms @204draws). The measurement tool itself pollutes feel + every worst-frame stat. True no-bridge steady state = CLEAN 30fps. Fix (L2): interval 500→2000ms, threshold-gated, ?frames=0 A/B.

**Controller self-pins at credit-0:** `CTRL_FRAME_BUDGET_MS=18` (cube_sphere.gd:169) vs the healthy 33ms full-radius floor → permanent-overload reading on 30fps-floor clients → optional streaming stuck at RELIEF_FLOOR forever. Fix (L5): adaptive setpoint (overload = worse than this client's own measured floor, or hitch-rate based); OR the draw cut un-pins it naturally.

**Draw composition @radius128 (204 draws):** ~60-90 active + ~20-40 neighbour 32³ mesh blocks (interiors solid → only surface blocks mesh) × ~2.1 material-surfaces/block (VoxelMesherBlocky = 1 surface per distinct per-block-id material; block_materials.gd gives every id its own StandardMaterial3D) + far-ring(1) + ~15 misc. **Materials are the cheap draw-cut axis, block size the strong one.**

**RANKED FIX PLAN (impact×effort):**
- Step 1 (days): **L1 far-ring packed-array rebuild** (post-crossing 157-381→≤30ms, best ratio in codebase) + **L2 capture hygiene** (kills 2Hz hitch, unpollutes measurement) + **L5 controller setpoint** (un-starve streaming). Then RE-BASELINE with frames off (all prior worst-frame data capture-polluted).
- Step 2 (1-2wk): **L3 texture atlas + ONE opaque material** (per-model UVs in the blocky library vs per-model materials; water keeps its own) → 204→~110 draws → 30→~20-24ms → mid clients 45-60fps, weak clean 30, controller recovers. Flag FP_ATLAS_MATERIAL. No engine rebuild.
- Step 3: **L4 64³ mesh-block godot_voxel patch** (verify FIRST why 32 is the cap — likely 16-bit index/vertex-count; risk: remesh-per-edit ×8) with L3 → ~40 draws → robust 60fps; OR settled-terrain bake (worst NEVER-OOM surface — only if L4 blocked). Then **L7 Forward+/WebGPU migration** (4.6+, order-of-magnitude per-draw cut, the true ceiling-breaker, blocked on upstream — [[voxiverse-godot-migration]]).

**DEAD ENDS (don't spend effort):** greedy meshing FOR FPS (prims trivial; doesn't cut draw calls — memory-only win); time_budget_ms/apply pacing (queue empty); GDScript-side hiding/merging of godot_voxel mesh blocks (it owns RIDs, no gate); radius shrink (user-vetoed); WebGPU NOW (not in 4.4). Inherent to web GL until L7: the vsync ladder, per-draw ANGLE cost, worker-vs-rAF core contention.

**Success criteria (measure with L2 landed, frames off):** walking p90 ≤33ms + zero >100ms frames over 10min; post-crossing worst ≤50ms; median ≥30fps Intel-HD tester, ≥45 after Step 2 mid client.
